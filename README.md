# animori-data

Русские названия аниме и соответствия номеров для [AniMori](https://github.com/foulnike/AniMori-AniList-Toolkit).
Собирается роботом, лежит в выпусках.

Зачем: без датасета каждое русское название при первом показе — сетевой запрос,
и список на сотню строк раскрашивается около двух минут. С датасетом список
выходит раскрашенным сразу, а сеть остаётся только для того, чего в файле нет.

**Состояние: клиент датасет пока не читает.** Первый выпуск собран и раздаётся,
а чтение в приложении ещё не написано — это следующий шаг. Всё, что ниже
сказано про поведение клиента, описывает замысел, а не сегодняшний день.

---

## Первый выпуск

Тег `2026.08.22-2005`, собран кнопкой, время работы 10 минут 9 секунд.

| Что                        | Сколько                    |
| -------------------------- | -------------------------- |
| Записей в файле имён       | 30 215                     |
| Из них с русским названием | 26 011                     |
| Соответствий MAL — AniList | 18 858                     |
| Запросов к Шикимори        | 612, все с ответом 200     |
| Вес                        | 1.04 МБ имён, 106 КБ карты |

Записи с пустым полем `russian` — 4 204 штуки — из файла не выбрасываются
намеренно. Пустое поле это не пропуск, а ответ: спрашивали, русского имени
нет. Выбрось их — и клиент пойдёт в сеть за каждым таким тайтлом при каждом
показе, то есть четыре тысячи запросов ради заведомо пустого ответа.

## Что в выпуске

```
index.json               опись: версия, дата, происхождение, размеры, отпечатки
titles-anime.json.gz     русские названия, шесть полей на тайтл
map-mal-anilist.json.gz  соответствия номеров MyAnimeList и AniList
```

Постоянные адреса, всегда указывающие на свежий выпуск:

```
https://github.com/foulnike/animori-data/releases/latest/download/index.json
https://github.com/foulnike/animori-data/releases/latest/download/titles-anime.json.gz
https://github.com/foulnike/animori-data/releases/latest/download/map-mal-anilist.json.gz
```

Замысел такой: клиент тянет только опись, а по ней видно, надо ли тянуть
остальное.

## Формы файлов

`index.json` — числа настоящие, из первого выпуска:

```json
{
  "version": 1,
  "builtAt": "2026-08-22T20:05:38.311Z",
  "source": "manami-project/anime-offline-database",
  "sourceTag": "2026-27",
  "license": "ODbL-1.0",
  "names": { "source": "shikimori.io", "count": 30215, "cyrillic": 26000 },
  "files": [{ "name": "titles-anime.json.gz", "bytes": 1089627, "sha256": "..." }]
}
```

Поле `names.count` подписано неудачно: это число **записей**, которые вернул
Шикимори, а не число русских имён. Имён меньше — 26 011. Подпись
исправляется следующей сборкой: `count` останется записями, а имена получат
своё поле.

`titles-anime.json.gz` после распаковки:

```json
{
  "v": 1,
  "tag": "2026-27",
  "builtAt": "2026-08-22T20:05:38.311Z",
  "count": 30215,
  "titles": [
    {
      "id": 5114,
      "name": "Fullmetal Alchemist: Brotherhood",
      "russian": "Стальной алхимик: Братство",
      "kind": "tv",
      "aired_on": "2009-04-05",
      "score": "9.1"
    }
  ]
}
```

Поле `id` — номер тайтла на Шикимори, он же номер MyAnimeList: для аниме
эти номера совпадают, и второго ключа не нужно.

`map-mal-anilist.json.gz` после распаковки:

```json
{
  "v": 1,
  "tag": "2026-27",
  "builtAt": "2026-08-22T20:05:38.311Z",
  "count": 18858,
  "pairs": [[5114, 5114]]
}
```

Пара — это `[номер MyAnimeList, номер AniList]`. Клиент живёт на номерах
AniList, а имена приезжают по номерам MyAnimeList: карта сшивает одно с другим.

Сжатие — gzip, а не zstd: gzip распаковывается штатными средствами браузера,
без сторонней библиотеки. В юзерскрипте лишняя библиотека — это лишние
килобайты в файле, который читает модерация Greasy Fork.

## Как собирается

`scripts/build-names.mjs`, запуск из `.github/workflows/build-names.yml`.

1. Из последнего выпуска манами берётся `anime-offline-database-minified.json`
   и из него — номера MyAnimeList и пары с AniList.
2. Шикимори опрашивается пачками по пятьдесят номеров с паузой 700 мс.
   Это вдвое мягче разрешённого: обход идёт раз в неделю, торопиться некуда.
3. Из ответа берётся шесть полей. Остальное отбрасывается сразу.
4. Файлы сжимаются, считаются отпечатки, пишется опись.
5. Выпуск создаётся отдельным шагом — и только если сборка набрала
   порог в двадцать тысяч названий и Шикимори узнал хотя бы девять
   номеров из десяти.

Адресов Шикимори три: `shikimori.io`, `shikimori.rip`, `shikimori.one`.
После трёх отказов подряд обход уходит на следующий. Прогон, где первый адрес
молчал на каждой пачке, уже случался — сборка обязана это пережить.

Провалившаяся сборка не публикует ничего. Клиенты в этом случае продолжают
жить на предыдущем выпуске, и это правильное поведение: половина датасета
хуже, чем его отсутствие.

Расписания пока нет: первый выпуск собран кнопкой. Оно ставится вместе
с личным токеном доступа — задача по расписанию отключается после 60 дней
без активности человека, а коммиты встроенного токена робота активностью
не считаются.

## Происхождение и лицензии

Номера и связки между сервисами — из [anime-offline-database](https://github.com/manami-project/anime-offline-database)
проекта manami, выпуск указан в `index.json` полем `sourceTag`.
База манами распространяется под ODbL-1.0, её содержимое — под DbCL-1.0.

Этот датасет — производная база и выходит на тех же условиях: **ODbL-1.0**,
см. `LICENSE`. Русские названия получены из открытого API Шикимори.

Код сборщика — MIT.
