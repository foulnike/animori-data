# animori-data

Русские названия аниме и соответствия номеров для [AniMori](https://github.com/foulnike/Animori-Desktop).
Собирается роботом, лежит в выпусках.

Зачем: без датасета каждое русское название при первом показе — сетевой запрос,
и список на сотню строк раскрашивается около двух минут. С датасетом список
выходит раскрашенным сразу, а сеть остаётся только для того, чего в файле нет.

**Состояние: работает.** Программа читает датасет начиная с версии 3.0.0:
путь имени начинается с него и только потом идёт в свои склады и в сеть.
Свежий выпуск — `2026.09.14-1012`.

**Источник — Шикимори, и обход наследует прошлый выпуск.** Раньше номера
и связки приходили из anime-offline-database проекта manami, а Шикимори
спрашивали по готовому списку номеров. База манами ушла в архив 4 июля 2026,
и вместе с ней ушла причина её читать: мёртвый список номеров устаревает
каждый сезон, а сборка вокруг него выглядит живой. Сборщик перечисляет каталог
Шикимори сам; своего номера выпуска у каталога нет, поэтому тег собирается
из старшего номера — `id-64973`. Номер растёт монотонно: два выпуска с одним
тегом означают, что каталог не двигался. Обычная неделя не перечисляет каталог
целиком и не спрашивает AniList про все тридцать тысяч номеров — и обход,
и карта берут семенем файлы прошлого выпуска; полный обход и пересборку карты
заказывают кнопкой.

---

## Обслуживание: одна обязанность

**Раз в два месяца открыть Actions → build-names → Run workflow.** Всё.

Обязанность не выдумана: задача по расписанию отключается после 60 дней
без человеческой активности в репозитории, а коммиты встроенного токена
активностью не считаются. Один запуск кнопкой сбрасывает этот счётчик
и заодно выкладывает свежий выпуск; тем же заходом разумно ставить галочку
`map_rebuild` — раз в пару месяцев карте полезно переспроситься целиком.
Секрет `ANIMORI_DATA_TOKEN` необязателен: с ним коммиты робота считаются
человеческой активностью, и расписание не уснёт вовсе.

Забыть не страшно. В репозитории программы каждое утро просыпается сторож
`watch-dataset`, и спрашивает он три разные вещи:

- **выходят ли выпуски вообще** — свежего нет десять дней, заводится задача,
  а GitHub присылает её письмом;
- **не отстало ли содержимое** — выпуски идут исправно, а старший номер
  каталога в них не двигается или отстал от живого больше чем на 400;
- **не застыла ли карта** — `map.builtAt` в описи старше 21 дня, то есть
  волна карты не доходит до AniList три понедельника подряд.

Первый вопрос ловит остановку сборки, второй — сборку, исправно выкладывающую
прошлогодний срез (дата свежая, содержимое мёртвое, жалоб нет), третий — то же
для карты: унаследованная карта неотличима от свежей ни числом пар, ни весом
файла. Сторож живёт в репозитории программы намеренно: здесь он уснул бы
вместе с тем, за чем следит. Появится нормальный выпуск — задача закроется
сама; об упавшей сборке GitHub пишет письмо сам.

Клиент при любом раскладе живёт на предыдущем выпуске и добирает недостающие
имена из сети по одному, поэтому пропущенная сборка — это медленнее,
а не сломано.

## Что в выпуске

```
index.json               опись: версия, дата, происхождение, свежесть, отпечатки
titles-anime.json.gz     русские названия, шесть полей на тайтл
map-mal-anilist.json.gz  соответствия номеров MyAnimeList и AniList
```

Постоянные адреса, всегда указывающие на свежий выпуск:

```
https://github.com/foulnike/animori-data/releases/latest/download/index.json
https://github.com/foulnike/animori-data/releases/latest/download/titles-anime.json.gz
https://github.com/foulnike/animori-data/releases/latest/download/map-mal-anilist.json.gz
```

Клиент тянет сначала опись и по ней решает, надо ли тянуть остальное:
совпала дата сборки — качать нечего. Саму опись он спрашивает условным
запросом: отпечаток `ETag` прошлой проверки уезжает в `If-None-Match`,
и неделя между выпусками проходит в ответах `304` без тела вовсе. Скачанные
файлы проверяются по отпечаткам из описи, распаковываются и складываются
в один файл в приватном каталоге программы.

Этими же адресами пользуются сборщик и сторож: сборщик берёт из описи прошлого
выпуска и числа для сравнения, и семена — файл имён и файл карты, — а сторож
старший номер каталога и возраст карты. Токен для этого не нужен, адреса
публичные.

## Формы файлов

`index.json` — числа из свежего выпуска `2026.09.14-1012`:

```json
{
  "version": 1,
  "builtAt": "2026-09-14T10:12:15.437Z",
  "source": "shikimori",
  "sourceTag": "id-64973",
  "license": "CC0-1.0",
  "names": {
    "source": "shikimori.rip",
    "count": 30546,
    "russian": 26292,
    "cyrillic": 26280,
    "known": 1,
    "mode": "partial",
    "fullAt": "2026-09-13T21:39:58.470Z",
    "added": 1,
    "changed": 17,
    "gone": null
  },
  "map": {
    "count": 20820,
    "from": "id-64973",
    "builtAt": "2026-09-14T10:12:15.437Z",
    "inherited": false,
    "rebuilt": false,
    "added": 0,
    "changed": 0,
    "dropped": 0,
    "kept": 0,
    "seeded": 20820,
    "wave": "отработала"
  },
  "freshness": {
    "maxId": 64973,
    "freshDays": 180,
    "airedRecent": 477,
    "released": 29606,
    "ongoing": 371,
    "anons": 569
  },
  "files": [{ "name": "titles-anime.json.gz", "bytes": 1221754, "sha256": "..." }]
}
```

Блок `names`:

- `count` — число **записей**, а не имён: записи с пустым `russian` считаются,
  пустота — это ответ, а не пропуск. `russian` — сколько записей несут русское
  имя; `cyrillic` — из них те, где встретилась кириллица. Имя латиницей
  в русском поле в мерку не попадает; приходит это от Шикимори, и подменять
  его ответ догадкой хуже, чем показать как есть.
- `known` — **мерка умерла.** Была долей номеров манами, которые Шикимори
  узнал; теперь номера и берутся у Шикимори, доля тождественно равна единице.
  Поле оставлено, чтобы не ломать чтение клиентом; приёмка держится
  на других порогах.
- `mode` — каким был обход: `full` или `partial`. `fullAt` — когда в последний
  раз полным; отметка передаётся из выпуска в выпуск, и по ней следующий
  прогон решает, пора ли идти полным: другой памяти у сборщика нет,
  в репозиторий он не пишет.
- `added`, `changed`, `gone` — разница против прошлого выпуска. Частичный обход
  пропаж не видит принципиально и пишет в `gone` null; полному разницу считают
  при записи выпуска, по тому же семени.
- `source` — зеркало, на котором обход **закончился**, а не начался.

Блок `map`:

- `count` — сколько пар в файле; `from` и `builtAt` — из какого выпуска они
  приехали.
- `inherited` — волна не внесла ни одной правки и не дошла до конца, то есть
  карта целиком из семени. Отличать это от «отработала, новых номеров
  не нашлось» обязательно: добавлено ноль в обоих случаях, но в первом карта
  неделю не свежая.
- `rebuilt` — прогон переспросил все пары до одной. Без этого признака
  освежённую карту не отличить от наращённой поверх старого ядра.
- `added`, `changed`, `dropped`, `kept` — добрано новых пар, переехало
  на другую запись AniList, убрано по доказанному отсутствию, оставлено
  от семени там, куда волна не добралась. Пересборка умеет уменьшать карту,
  и молчать об этом нельзя: по числу пар убыль не видна. `seeded` — сколько
  пар пришло из семени.
- `wave` — состояние волны словами: `отработала`, `свёрнута`, `выключена`,
  `доступ закрыт`.

Блок `freshness`:

- `maxId` — старший номер каталога на момент обхода, главное число блока:
  сторож сравнивает его с тем, что Шикимори отдаёт прямо сейчас, и отличает
  живой срез от прошлогоднего.
- `freshDays` — ширина окна свежести в днях, сейчас 180. `airedRecent` —
  сколько тайтлов вышло в этом окне; оно закрыто с двух сторон, иначе анонсы
  на следующий год изображали бы бурную свежесть, а в само число анонсы
  не входят вовсе.
- `released`, `ongoing`, `anons` — разбивка каталога по состоянию.

`titles-anime.json.gz` после распаковки:

```json
{
  "v": 1,
  "tag": "id-64973",
  "builtAt": "2026-09-14T10:12:15.437Z",
  "count": 30546,
  "titles": [
    {
      "id": 5114,
      "name": "Fullmetal Alchemist: Brotherhood",
      "russian": "Стальной алхимик: Братство",
      "kind": "tv",
      "aired_on": "2009-04-05",
      "score": "9.1"
    }
  ]
}
```

Поле `id` — номер тайтла на Шикимори, он же номер MyAnimeList: для аниме эти
номера совпадают. Записи с пустым `russian` из файла не выбрасываются: пустое
поле — это ответ «русского имени нет», а не пропуск, и клиент читает его
буквально — «в выпуске пусто» означает «за именем не ходить». Выбрось их —
и тысячи запросов в неделю уйдут ради заведомо пустого ответа.

`map-mal-anilist.json.gz` после распаковки:

```json
{ "v": 1, "tag": "id-64973", "builtAt": "2026-09-14T10:12:15.437Z", "count": 20820, "pairs": [[5114, 5114]] }
```

Пара — это `[номер MyAnimeList, номер AniList]`: клиент живёт на номерах
AniList, а имена приезжают по номерам MyAnimeList. Карта — страховка,
а не основной путь: номер MAL приходит вместе с медиа и хранится в снимке.
Голова у файла карты своя: когда пары унаследованы целиком, `tag` и `builtAt`
называют выпуск, из которого они пришли, — иначе файл врал бы сам про себя.

Сжатие — gzip, а не zstd: gzip распаковывается штатными средствами браузера.

## Как собирается

`scripts/build-names.mjs`, запуск из `.github/workflows/build-names.yml`.
Зависимостей у сборщика нет: всё нужное есть в Node из коробки.
Перечисление каталога лежит в `scripts/crawl.mjs`, запись выпуска
и отчёт — в `scripts/release-files.mjs`, волны обогащения —
в `scripts/enrich-map.mjs` и `scripts/enrich-names.mjs`, общее мелкое —
в `scripts/common.mjs`.

1. **Семена прошлого выпуска.** Опись прошлого выпуска даёт числа
   для сравнения, файл имён — семя обхода, файл карты — семя волны AniList.
   Оба сжатых файла проверяются по отпечаткам до распаковки, как это делает
   клиент; порченое или подозрительно маленькое семя отбрасывается целиком:
   добирать хвост к половине каталога значило бы выпустить половину
   и не заметить.

2. **План времени.** Прогон объявляет свой срок сразу после обхода: всему —
   `RUN_BUDGET` 300 минут, волне карты `MAP_BUDGET` 150, волне имён
   `NAMES_BUDGET` 60, выпуску три. Каждая волна сворачивается сама и отдаёт
   собранное. План нужен затем, что потолок задания GitHub — глухая отмена:
   она убивает и файлы, и выпуск, и час обхода заодно. Так и вышло 12 сентября
   2026 — прогон отменили по потолку 120 минут: два часа работы, ни файлов,
   ни выпуска, ни причины в логе. Теперь потолок стоит на 350 минутах
   и остаётся страховкой от зависания, а рабочий срок — свой.

3. **Обход каталога** — `GET /api/animes?page=N&limit=50&order=id&censored=false`;
   пятьдесят — потолок Шикимори, `limit=100` молча отдаёт те же пятьдесят.

   **Частичный** обход — обычная неделя: спрашивается только то, что впрямь
   могло измениться — хвост за прошлой головой плюс целиком списки идущего
   и анонсов. Это десятки страниц вместо шестисот одиннадцати.
   **Полный** идёт страница за страницей до пустого массива: 12.5 минуты
   при паузе 700 мс, 612 ответов 200. Полный случается, когда наследовать
   нечего или когда со времени прошлого полного прошло больше тридцати дней:
   редкие правки названий у давно вышедшего частичный обход не видит.
   `BUILD_MODE=full` и `partial` говорят прямо, `auto` смотрит на `names.fullAt`.

   `censored=false` — не украшение: без флага каталог обрывается на шесть
   тысяч записей раньше, и голова его другая (с флагом 64905, без 64898).

4. **Пороги приёмки — до волн.** Проверки против одной беды: молча выложить
   обрубок вместо каталога.

   - не меньше 25 000 названий;
   - усадка против прошлого выпуска не больше 5%;
   - старший номер не ниже, чем в прошлом выпуске;
   - карта не меньше своего семени тем же порогом в 5%, а если семени
     не было — не пуста.

   База сравнения — опись прошлого выпуска по постоянному адресу; прошлого
   выпуска нет или адрес не ответил — сравнительные проверки молчат, остаётся
   нижний порог. Порог карты считается после волны — раньше не по чему —
   и берёт не голое число пар, а число вместе с доказанными покойниками:
   уборку по успешному ответу AniList он усадкой не считает, иначе честная
   пересборка ронялась бы ровно за то, ради чего её просили. Провалились —
   сборка падает сейчас, а не через час обогащения, которое некуда публиковать.

5. **Волна карты.** Пары MAL → AniList больше брать негде: они приходили
   из манами готовыми. Номера спрашиваются у AniList пачками по пятьдесят
   (`idMal_in`): обычная неделя — только те, которых нет в семени, десятки
   запросов; полная пересборка (`map_rebuild`, то же что `BUILD_MAP_SEED=off`)
   — все 611, 26.9 минуты по замеру 13 сентября 2026.

   **Семя в пересборке не отменяется, а работает опорой.** Пара уходит
   из карты только там, где AniList ответил успешно и пары в ответе
   не оказалось; номер, до которого волна не дошла, едет как был. Поэтому
   неделя, в которую AniList не отвечает вовсе, отдаёт карту прошлой недели,
   а не пустой файл. Плата за это — карта умеет застывать незаметно,
   поэтому её возраст назван и в описи, и в файле карты, и в описании выпуска.

   Пауза между пачками — 2500 мс: документация обещает девяносто запросов
   в минуту, замер показал `X-RateLimit-Limit: 30`. Прежние 2100 мс давали
   двадцать восемь в минуту, то есть жизнь на самой кромке — прогон
   13 сентября 2026 собрал восемьдесят восемь отказов 429 с минутным
   ожиданием каждый. Волна умеет сама растягивать паузу на 429 и осторожно
   сжимать её обратно, но лучше не доводить. 5 сентября 2026 AniList начал
   отвечать 403 без заголовков `Origin` и `Referer` своего домена; отказ снят,
   но волна узнаёт его по телу, сворачивается и пишет `wave: доступ закрыт`.

   Перечислить AniList так же, как Шикимори, нельзя, и это не лень: выдача
   обрезана на 5 000 записях, страница 400 отвечает ошибкой, а `id_greater`
   у `Media` не существует. AniList годится только как доводчик по известным
   номерам.

6. **Волна имён.** Тайтлы, для которых Шикимори русского имени не дал,
   добираются из anime365 по одному номеру MAL за запрос; имя принимается
   только с кириллицей — латиница в поле `ru` это то же английское название.
   Отдача у волны низкая, и это свойство источника: 13 сентября час работы дал
   **36 имён** на 4 021 спрошенный тайтл из 4 295 пустых. Поэтому у волны есть
   журнал `.github/anime365-empty.json`: номер, на который ответили «русского
   имени нет», не переспрашивается 180 дней (`NAMES_RETRY_DAYS`). Очередь идёт
   от больших номеров к меньшим: бюджета может не хватить на всех, а у новинки
   шанс выше. Журнал едет в репозиторий тем же коммитом, что
   и `.github/last-build`, и только после удавшегося выпуска; в сам выпуск
   он не кладётся — клиентам он ни к чему.

7. Файлы сжимаются, считаются отпечатки, пишется опись и описание выпуска,
   выпуск создаётся отдельным шагом. Провалившаяся сборка не публикует ничего
   и падает громко: причина уходит в итог прогона, а не только в лог шага.
   Половина датасета хуже, чем его отсутствие.

Адреса Шикимори — `shikimori.rip`, `shikimori.io`, `shikimori.one`, в этом
порядке (из замера: `rip` не отказал ни разу); после трёх отказов подряд обход
уходит на следующий адрес, а на 429 повторяет страницу, подождав столько,
сколько попросил сервер, но не меньше пяти секунд. У anime365 адресов два:
`anime365.ru` и `smotret-anime.online`.

Встроенный токен GitHub сборщику не нужен: единственное, что он читает
со стороны, — свой прошлый выпуск, а он публичен. Обе волны — необязательные
пристройки: любую можно выключить входом `waves` или переменными
`BUILD_ANILIST=off` / `BUILD_ANIME365=off`.

### Расписание

Понедельник, 04:27 UTC, плюс запуск кнопкой. Минуты не круглые намеренно:
в начале часа очередь задач у GitHub самая длинная. Обычная неделя стоит
**13 минут**, самый дорогой из виденных прогонов — 100. Запуск по расписанию
публикует всегда, гоняет обе волны и карту не пересобирает; две сборки разом
не сходятся.

Входы ручного запуска:

| Вход            | Что делает                                                        |
| --------------- | ----------------------------------------------------------------- |
| `pause`         | пауза между страницами Шикимори в миллисекундах, по умолчанию 700 |
| `anilist_pause` | пауза между пачками AniList в миллисекундах, по умолчанию 2500    |
| `publish`       | снять галочку — собрать и посмотреть итог, ничего не выпуская      |
| `waves`         | какие волны гонять: обе, только карта, только имена, никакие       |
| `map_rebuild`   | переспросить у AniList все пары до одной                           |
| `names_full`    | обойти каталог полностью, не дожидаясь планового полного           |
| `budget`        | бюджет волны имён в минутах, по умолчанию 60                       |
| `run_budget`    | собственный срок всего прогона в минутах, по умолчанию 300         |
| `map_budget`    | сколько из них позволено волне карты, по умолчанию 150             |

Оба ручных режима расписанию недоступны намеренно: пустое поле даёт обычный
ход с семенем и `auto`. Полчаса и шестьсот запросов каждую неделю ни к чему.

После удавшегося выпуска робот пишет тег в `.github/last-build`, а рядом
едет журнал волны имён — след в истории репозитория.
