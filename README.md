# animori-data

Русские названия аниме и соответствия номеров для [AniMori](https://github.com/foulnike/AniMori-AniList-Toolkit).
Собирается роботом, лежит в выпусках.

Зачем: без датасета каждое русское название при первом показе — сетевой запрос,
и список на сотню строк раскрашивается около двух минут. С датасетом список
выходит раскрашенным сразу, а сеть остаётся только для того, чего в файле нет.

**Состояние: клиент датасет читает.** В версии 3.0 путь имени начинается
с датасета и только потом идёт в свои склады и в сеть. Выпущенной сборки
пока нет — чтение живёт в ветке разработки `app-3.0-dev`.

**Сентябрь 2026: источник сменился.** Раньше номера и связки между сервисами
приходили из anime-offline-database проекта manami, а Шикимори спрашивали
уже по готовому списку номеров. База манами ушла в архив 4 июля 2026,
и вместе с ней ушла причина её читать: мёртвый список номеров устаревает
каждый сезон, а сборка вокруг него выглядит живой. Сборщик теперь перечисляет
каталог Шикимори сам. Что это поменяло в файлах — ниже.

**Сентябрь 2026, вторая правка: сборка стала наследовать свой прошлый выпуск.**
Обычная неделя больше не перечисляет каталог целиком и не спрашивает AniList
про все тридцать тысяч номеров: и обход, и карта берут семенем файлы прошлого
выпуска. Полный обход остался, но случается редко — подробности ниже.

## Обслуживание: одна обязанность

**Раз в два месяца открыть Actions → build-names → Run workflow.** Всё.

Обязанность не выдумана: задача по расписанию отключается после 60 дней
без человеческой активности в репозитории, а коммиты встроенного токена
активностью не считаются. Один запуск кнопкой сбрасывает этот счётчик
и заодно выкладывает свежий выпуск.

Забыть не страшно. В репозитории программы каждое утро просыпается сторож
`watch-dataset`, и спрашивает он две разные вещи:

- **выходят ли выпуски вообще** — свежего нет десять дней, заводится задача
  (issue), а GitHub присылает её письмом;
- **не отстало ли содержимое** — выпуски идут исправно, а старший номер
  каталога в них не двигается или отстал от живого больше чем на 400.

Второй вопрос появился не от любви к порядку. Прежний сторож смотрел только
на дату выпуска — и сборка, исправно выкладывающая по расписанию прошлогодний
срез, проходила мимо надзора целиком. Дата свежая, содержимое мёртвое,
жалоб нет.

Появится нормальный выпуск — задача закроется сама. Об упавшей сборке GitHub
пишет письмо сам.

Клиент при любом раскладе живёт на предыдущем выпуске и добирает недостающие
имена из сети по одному, поэтому пропущенная сборка — это медленнее,
а не сломано.

Подробная памятка — что делать по письму сторожа, куда смотреть у красного
прогона и как проверить датасет со стороны программы — в `docs/DATASET-MAINTENANCE.md`
репозитория AniMori.

## Что в выпуске

```
index.json               опись: версия, дата, происхождение, свежесть, отпечатки
titles-anime.json.gz     русские названия, шесть полей на тайтл
map-mal-anilist.json.gz  соответствия номеров MyAnimeList и AniList
```

Постоянные адреса, всегда указывающие на свежий выпуск:

```
https://github.com/foulnike/animori-data/releases/latest/download/index.json
https://github.com/foulnike/animori-data/releases/latest/download/titles-anime.json.gz
https://github.com/foulnike/animori-data/releases/latest/download/map-mal-anilist.json.gz
```

Клиент тянет сначала опись и по ней решает, надо ли тянуть остальное:
совпала дата сборки — качать нечего. Саму опись он спрашивает условным
запросом: отпечаток `ETag` прошлой проверки уезжает в `If-None-Match`,
и неделя между выпусками проходит в ответах `304` без тела вовсе. Скачанные
файлы проверяются по отпечаткам из описи, распаковываются и складываются
в один файл в приватном каталоге программы.

Этими же адресами пользуются сборщик и сторож: сборщик берёт из описи прошлого
выпуска и числа для сравнения, и семена — файл имён и файл карты, — а сторож
старший номер каталога. Токен для этого не нужен, адреса публичные.

## Формы файлов

`index.json`:

```json
{
  "version": 1,
  "builtAt": "2026-09-03T05:12:44.108Z",
  "source": "shikimori",
  "sourceTag": "id-64905",
  "license": "CC0-1.0",
  "names": {
    "source": "shikimori.rip",
    "count": 30473,
    "russian": 26220,
    "cyrillic": 26208,
    "known": 1,
    "mode": "partial",
    "fullAt": "2026-09-03T05:12:44.108Z",
    "added": 12,
    "changed": 87
  },
  "map": {
    "count": 20788,
    "from": "id-64905",
    "builtAt": "2026-09-03T05:12:44.108Z",
    "inherited": false,
    "added": 9,
    "seeded": 20779,
    "wave": "отработала"
  },
  "freshness": {
    "maxId": 64905,
    "freshDays": 180,
    "airedRecent": 458,
    "released": 29533,
    "ongoing": 371,
    "anons": 569
  },
  "files": [{ "name": "titles-anime.json.gz", "bytes": 1089627, "sha256": "..." }]
}
```

Числа здесь — из прогона 3 сентября 2026; в каждом живом выпуске они свои.

`source` и `sourceTag` читаются так. Источник теперь один, и он назван прямо:
`shikimori`. Своего номера выпуска у каталога нет, а срез чем-то обозначать
надо, поэтому тег собран из старшего номера каталога: `id-64905`. Номер растёт
монотонно и сам по себе служит меркой — два выпуска с одинаковым тегом
означают, что каталог не двигался.

Был этот тег недельным тегом манами вида `2026-27`. Формат сменился насовсем.

Блок `names`:

- `count` — число **записей** в файле имён, а не число имён. Записи с пустым
  полем `russian` тоже считаются: пустота — это ответ, а не пропуск.
- `russian` — сколько записей реально несут русское имя.
- `cyrillic` — из них те, в которых встретилась кириллица. Мерка уже узкая:
  имя латиницей в поле `russian` в неё не попадает. Расхождение мелкое,
  но живое: в прогоне 3 сентября 26 220 против 26 208, то есть двенадцать
  записей несут в русском поле латиницу.
- `known` — **мерка умерла.** Это была доля номеров манами, которые Шикимори
  сумел узнать; порог `0.9` не пускал в выпуск сборку, потерявшую связь
  с источником. Теперь номера и берутся у Шикимори, так что доля тождественно
  равна единице и ничего не проверяет. Поле оставлено, чтобы не ломать чтение
  клиентом; приёмка держится на других порогах — они ниже.
- `mode` — каким был обход этого прогона: `full` или `partial`.
- `fullAt` — когда в последний раз обход был полным. Отметка передаётся
  из выпуска в выпуск, и по ней следующий прогон решает, пора ли идти полным.
  Другого места для этой памяти нет: сборщик в репозиторий не пишет вовсе.
- `added` и `changed` — сколько записей прогон добавил и сколько обновил.
  У полного обхода это числа против семени, если оно было.
- `source` — то зеркало, на котором обход **закончился**, а не то,
  с которого начинался. При уходе на запасной адрес в описи окажется он.

Блок `map` — про карту номеров и, главное, про её возраст:

- `count` — сколько пар в файле.
- `from` и `builtAt` — из какого выпуска пары приехали. Совпадают
  с сегодняшним прогоном, когда волна отработала.
- `inherited` — карта унаследована от семени целиком, то есть AniList
  в этот прогон ничего не добавил. Отличать это от «волна отработала,
  новых номеров не нашлось» обязательно: в обоих случаях добавлено ноль,
  но в первом карта неделю не свежая.
- `added` и `seeded` — сколько пар добрано в этот прогон и сколько пришло
  из семени.
- `wave` — состояние волны словами: `отработала`, `свёрнута`, `выключена`
  или `доступ закрыт`.

Блок `freshness` — про то, чего не хватало надзору:

- `maxId` — старший номер каталога на момент обхода. Главное число блока:
  по нему сторож отличает живой срез от прошлогоднего, сравнивая его с тем,
  что Шикимори отдаёт прямо сейчас.
- `freshDays` — ширина окна свежести в днях, сейчас 180.
- `airedRecent` — сколько тайтлов вышло в этом окне. Окно закрыто с двух
  сторон намеренно: будущие даты в него не попадают, иначе анонсы
  на следующий год изображали бы бурную свежесть.
- `released`, `ongoing`, `anons` — разбивка каталога по состоянию.
  Анонсы в `airedRecent` не считаются вовсе.

`titles-anime.json.gz` после распаковки — форма не менялась, только тег:

```json
{
  "v": 1,
  "tag": "id-64905",
  "builtAt": "2026-09-03T05:12:44.108Z",
  "count": 30473,
  "titles": [
    {
      "id": 5114,
      "name": "Fullmetal Alchemist: Brotherhood",
      "russian": "Стальной алхимик: Братство",
      "kind": "tv",
      "aired_on": "2009-04-05",
      "score": "9.1"
    }
  ]
}
```

Поле `id` — номер тайтла на Шикимори, он же номер MyAnimeList: для аниме
эти номера совпадают, и второго ключа не нужно.

Записи с пустым `russian` из файла не выбрасываются намеренно. Пустое поле
это не пропуск, а ответ: спрашивали, русского имени нет. Выбрось их — и клиент
пойдёт в сеть за каждым таким тайтлом при каждом показе, то есть тысячи
запросов ради заведомо пустого ответа. Клиент этим ответом пользуется
буквально: «в выпуске пусто» означает «за именем не ходить».

`map-mal-anilist.json.gz` после распаковки:

```json
{
  "v": 1,
  "tag": "id-64905",
  "builtAt": "2026-09-03T05:12:44.108Z",
  "count": 20788,
  "pairs": [[5114, 5114]]
}
```

Пара — это `[номер MyAnimeList, номер AniList]`. Клиент живёт на номерах
AniList, а имена приезжают по номерам MyAnimeList: карта сшивает одно с другим.
Карта — страховка, а не основной путь: номер MAL приходит вместе с медиа
в поиске, карточке и списке и хранится в снимке.

Голова у файла карты своя: когда пары унаследованы целиком, `tag` и `builtAt`
в нём называют выпуск, из которого пары пришли, а не сегодняшний прогон.
Иначе файл врал бы сам про себя, и застой не был бы виден даже в нём.

Сжатие — gzip, а не zstd: gzip распаковывается штатными средствами браузера,
без сторонней библиотеки.

## Как собирается

`scripts/build-names.mjs`, запуск из `.github/workflows/build-names.yml`.
Зависимостей у сборщика нет: всё нужное есть в Node из коробки.
Перечисление каталога лежит в `scripts/crawl.mjs`, запись выпуска
и отчёт — в `scripts/release-files.mjs`, волны обогащения —
в `scripts/enrich-map.mjs` и `scripts/enrich-names.mjs`, общее мелкое —
в `scripts/common.mjs`.

1. **Семена прошлого выпуска.** Опись прошлого выпуска даёт числа
   для сравнения, файл имён — семя обхода, файл карты — семя волны AniList.
   Оба сжатых файла проверяются по отпечаткам до распаковки, как это делает
   клиент. Порченое или подозрительно маленькое семя отбрасывается целиком:
   добирать хвост к половине каталога значило бы выпустить половину
   и не заметить этого.

2. **Обход каталога** — `GET /api/animes?page=N&limit=50&order=id&censored=false`.
   Пятьдесят — потолок Шикимори: `limit=100` молча отдаёт те же пятьдесят.

   Обход бывает двух видов. **Частичный** — обычная неделя: спрашивается
   только то, что впрямь могло измениться — хвост за прошлой головой
   и целиком списки идущего и анонсов. Это десятки страниц вместо шестисот
   десяти. **Полный** перечисляет каталог страница за страницей, пока
   не придёт пустой массив; замер такого прогона — 11.5 минуты при паузе
   700 мс, 611 ответов с кодом 200, 610 страниц. Номера, пришедшие дважды
   на границах страниц, отбрасываются по множеству увиденных.

   Полный случается, когда наследовать нечего (первый прогон, потеря или
   порча семени) или когда со времени прошлого полного вышло больше тридцати
   дней. Второе — не формальность: редкие правки названий у давно вышедшего
   частичный обход не видит, и копиться им вечно нельзя. Тридцать дней —
   это четыре-пять недельных прогонов подряд. `BUILD_MODE=full` и `partial`
   говорят прямо, `auto` смотрит на отметку `names.fullAt` в описи.

   `censored=false` — не украшение. Без этого флага каталог обрывается
   примерно на шесть тысяч записей раньше, и голова его другая. Проверено
   замером, а не вычитано: с флагом старший номер 64905, без флага 64898,
   и кончается такой каталог где-то в районе двадцати четырёх тысяч записей.

3. **Пороги приёмки — до волн.** Проверки против одной беды: молча выложить
   обрубок вместо каталога.

   - не меньше 25 000 названий;
   - усадка против прошлого выпуска не больше 5%;
   - старший номер не ниже, чем в прошлом выпуске;
   - карта не меньше своего семени тем же порогом в 5%, а если семени
     не было — не пуста.

   База сравнения — опись прошлого выпуска по постоянному адресу. Прошлого
   выпуска нет или адрес не ответил — сравнительные проверки молчат,
   остаётся нижний порог. Провалились — сборка падает сейчас, а не через
   час обогащения, которое всё равно некуда публиковать.

   Порог у карты появился позже остальных, и появился он не зря: это была
   ровно та щель, через которую пустая карта уезжала бы в выпуск при зелёном
   прогоне.

   Прежние пороги были другими: двадцать тысяч названий и девяносто процентов
   узнанных номеров. Второй из них теперь бессмыслен (см. `known` выше),
   поэтому его заменили проверки, сравнивающие выпуск с предыдущим.

4. **Волна карты.** Пары MAL → AniList больше брать негде: они приходили
   из манами готовыми. Номера спрашиваются у AniList пачками по пятьдесят
   (`idMal_in`), но только те, которых нет в семени. Обычная неделя стоит
   поэтому десятки запросов, а не шестьсот десять; замер полного прогона
   без семени — 22.6 минуты.

   У семени есть и второе, более важное следствие: неделя, в которую AniList
   не отвечает вовсе, отдаёт в выпуск карту прошлой недели, а не пустой файл.
   Плата за это — карта умеет застывать незаметно, ровно как застыл бы вход
   на манами. Поэтому её возраст назван и в описи (блок `map`), и в самом
   файле карты, и в описании выпуска.

   Пар вышло 20 788 против 20 929 в последнем выпуске эпохи манами:
   перечисление отдаёт то же покрытие, что и мёртвая база, — потеря
   в полторы сотни пар на тридцать тысяч записей.

   Пауза между пачками — 2100 мс, а не 1200. Документация AniList обещает
   девяносто запросов в минуту, а замер показал `X-RateLimit-Limit: 30`.
   При 1200 мс волна жила на отказах 429 и рисковала свернуться
   по счётчику подряд идущих неудач.

   Перечислить AniList так же, как Шикимори, нельзя, и это не лень:
   выдача обрезана на 5 000 записях (сто страниц по пятьдесят), страница 400
   отвечает ошибкой 400, а аргумента `id_greater` у `Media` не существует.
   AniList годится только как доводчик по известным номерам.

5. **Волна имён.** Тайтлы, для которых Шикимори русского имени не дал,
   добираются из anime365 по одному номеру MAL за запрос. Имя принимается
   только с кириллицей: латиница в поле `ru` — это то же английское название,
   и подсовывать его как перевод нельзя. У волны есть бюджет времени
   (по умолчанию 60 минут), по истечении она сворачивается и отдаёт что успела.

   Отдача у этой волны низкая, и это свойство источника, а не настройки:
   в прогоне 3 сентября час работы дал **38 имён** на 4 063 спрошенных тайтла
   из 4 291 пустых. anime365 просто не знает того, что осталось без русского
   имени у Шикимори.

   Поэтому у волны есть журнал — `.github/anime365-empty.json`. Ответ
   «русского имени нет» записывается туда датой, и тот же номер
   не переспрашивается 180 дней (`NAMES_RETRY_DAYS`); нашлось имя — строка
   из журнала уходит. Первая неделя после появления журнала стоит как раньше,
   дальше вместо четырёх тысяч запросов остаются десятки. Очередь идёт
   от больших номеров к меньшим: бюджета может не хватить на всех,
   а у новинки шанс получить перевод выше. Журнал едет в репозиторий тем
   же коммитом, что и `.github/last-build`, и только после удавшегося
   выпуска; в сам выпуск он не кладётся — клиентам он ни к чему.

6. Файлы сжимаются, считаются отпечатки, пишется опись и описание выпуска.
7. Выпуск создаётся отдельным шагом.

Адреса Шикимори — `shikimori.rip`, `shikimori.io`, `shikimori.one`, в этом
порядке. Порядок из замера: `rip` не отказал ни разу, `io` один раз из шести,
`one` дал два таймаута из четырёх проб — поэтому он последний, а в стороже
его нет вовсе. После трёх отказов подряд обход уходит на следующий адрес,
а на 429 повторяет ту же страницу, подождав столько, сколько попросил сервер,
но не меньше пяти секунд. У anime365 адресов два: `anime365.ru`
и `smotret-anime.online`.

Встроенный токен GitHub сборщику больше не нужен и шагу сборки не отдаётся:
он был нужен ради чтения выпусков манами. Единственное, что сборщик читает
со стороны, — свой прошлый выпуск, а он публичен.

Провалившаяся сборка не публикует ничего и падает громко: причина уходит
и в итог прогона, а не только в лог шага. Клиенты в этом случае продолжают
жить на предыдущем выпуске, и это правильное поведение: половина датасета
хуже, чем его отсутствие.

Обе волны — необязательные пристройки, а не часть фундамента. Любую можно
выключить входом `waves` или переменными `BUILD_ANILIST=off` / `BUILD_ANIME365=off`,
и сборка соберётся ровно тем, что дал Шикимори.

### Расписание

Понедельник, 04:27 UTC, плюс запуск кнопкой. Раньше понедельник был привязан
к недельному выпуску манами, который появлялся на выходных. Привязки больше
нет: раз в неделю — это теперь просто про цену прогона, каталог можно
перечислять когда угодно. Минуты не круглые намеренно: в начале часа очередь
задач у GitHub самая длинная.

Потолок прогона — 120 минут. Обычная неделя в него укладывается легко:
частичный обход и волна карты с семенем — это минуты, а волна имён с журналом
выбирает разве что остатки. Дорогой прогон — полный обход с пустым журналом:
обход 11.5 минуты, волна карты до 22.6, волна имён упирается в свой бюджет.
Запуск по расписанию публикует всегда и гоняет обе волны. Две сборки разом
не сходятся: идущая дорабатывает до конца, вторая ждёт.

Входы ручного запуска:

| Вход            | Что делает                                                       |
| --------------- | ---------------------------------------------------------------- |
| `pause`         | пауза между страницами Шикимори в миллисекундах, по умолчанию 700 |
| `anilist_pause` | пауза между пачками AniList в миллисекундах, по умолчанию 2100    |
| `publish`       | снять галочку — собрать и посмотреть итог, ничего не выпуская      |
| `waves`         | какие волны гонять: обе, только карта, только имена, никакие       |
| `budget`        | бюджет волны имён в минутах, по умолчанию 60                       |

Вид обхода входом пока не задаётся: `BUILD_MODE` читается из окружения,
а в списке входов его нет. Обычному прогону он и не нужен — `auto`
справляется сам.

После удавшегося выпуска робот пишет тег в `.github/last-build`, а рядом
едет журнал волны имён. Это не украшение, а след в истории репозитория.
Секрет `ANIMORI_DATA_TOKEN` необязателен: пока его нет, шаг выпуска берёт
встроенный токен и всё работает. Он нужен только тем, кто хочет, чтобы
коммиты робота считались человеческой активностью, — тогда расписание
не уснёт и без ручных заходов.

## Происхождение и лицензия

Датасет — **CC0-1.0**, см. `LICENSE`. Это общественное достояние: права
не удерживаются, условий нет, атрибуция — просьба, а не требование.

Раньше здесь стояла ODbL-1.0, и стояла не по выбору: база манами выходит
под этой лицензией, а производная от неё обязана выходить на тех же условиях.
Производной больше нет — манами не читается ни строчкой. Ни Шикимори,
ни anime365, ни AniList условий распространения на выгрузку через открытый
API не накладывают, так что условия выбираем мы.

Почему CC0, а не MIT, который стоял здесь несколько дней: MIT — лицензия
для кода, и к сводке фактов она прикладывается с натяжкой. CC0 написана
ровно под такое: она отдельно называет права на базы данных и права
на извлечение и повторное использование данных (пункты 1(v) и 1(vi) её
текста) — то есть закрывает именно тот слой прав, который у сводки номеров
и названий и возникает. Практический смысл прежний: пользуйтесь как угодно,
спрос не с нас. Но теперь он выражен инструментом, сделанным для данных,
а не для программ.

Код сборщика лежит в этом же репозитории и отдаётся на тех же условиях:
разводить две лицензии ради сотни строк на Node смысла нет.

Данные: номера, названия, даты выхода, оценки — это факты, полученные
из открытых API Шикимори и anime365, плюс номера AniList. Авторские тексты
в датасет не входят и не войдут: ни описаний, ни синопсисов. То же про Kodik —
его `material_data` живёт только в памяти работающей программы, в файлы
выпуска оно не попадает никогда.

Атрибуция стоит в описании каждого выпуска и в самой программе, в разделе
«О программе». CC0 её не требует — оставлена намеренно.
